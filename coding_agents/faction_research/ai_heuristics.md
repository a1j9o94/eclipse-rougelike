# Strategy archive: AI hypotheses and implementation assessment

Research date: 2026-09-19. This document changes no AI behavior. The outcome of a future implementation would be an opponent that turns resources and military advantages into points, with understandable, situational choices and bounded server computation.

## Ruleset boundaries

These are strategy opinions and hypotheses, not mechanical specifications. S1 explicitly assumes six players, rare technologies, warp portals, and optionally minor species/turn-order variants. S2 principally addresses four to six players and discusses other content such as Worlds Afar. Neither justifies importing quoted tile probabilities, combat percentages, or fixed opening scripts into every match.

S4’s recommendation that Neutron Bombs are essential refers to a **six-population Galactic Center**, and names **The Swarm** and **Heralds of Ragnarok**. Those conditions are not the current base-game setup. Its recommendation becomes much stronger in a ruleset with dense population and no suitable cannon alternative; it is not a universal priority.

The separately extracted **May 2026 house rules** specify **ten rounds**, all technologies available from setup, removal of Neutron Absorber, and public deterministic reputation upgrades. All materially change this assessment: longer income payback, no unknown future technology draws, fewer bombardment counters, and exact public combat scoring. Older twelve-round material, if retained in the archive, must be versioned separately rather than averaged with ten rounds. The assigned strategy/tips extracts do not establish a twelve-round rule. Current matches remain eight rounds and keep opponents’ reputation private. The [collection overview](README.md) records precedence and variant scope.

Other caution points: the compilation calls Improved Hull both two hull and, in an emphatic note, “+3 health”; do not use that inconsistency to rewrite the component. Likewise, old battle-calculator percentages and resource projections need recomputation against the selected catalog and authoritative rules. Source claims about guaranteed winning scores, ideal faction playstyles, or retaliation in later games are not acceptance criteria. Cross-match retaliation is excluded from fair AI.

## What is already implemented

This assessment reads the current working tree, including the faction-registry refactor underway. Links name stable modules/functions rather than relying on temporary line numbers.

- [ai.ts](../../shared/eclipse/ai.ts): `sectorControlValue` already considers printed VP, production, faction scoring, and nonlinear marginal upkeep. Money receives more value when reserves are low. `technologyValue` already boosts early Improved Hull and conditionally boosts Neutron Bombs near populated opponents. Advanced population technology counts eligible squares. `evaluateAiCommand` penalizes action-induced shortfalls and conversions; it has faction capability biases, batch-build value, treaty-breaking penalties, and a coarse late research-track bonus.
- [aiCandidates.ts](../../shared/eclipse/aiCandidates.ts): bounded candidates already include funded purchases, coordinated builds, blueprint edits, and movement routes spending multiple activations. More search depth cannot select a useful plan that candidate generation never offers.
- [aiSimulation.ts](../../shared/eclipse/aiSimulation.ts) and `chooseAiCommand`: public blueprint matchup estimates already influence attacks/retreats. The fast policy uses 16 trials per cached matchup. The model documents limitations including voluntary retreats, tied initiative decisions, and multiple-owner battles. These estimates are not exact tactical guarantees.
- [aiEvaluation.ts](../../shared/eclipse/aiEvaluation.ts): evaluation already incorporates scoring, shortfalls, limited production horizons, colony-ship-limited population potential, fleet survival/value, territory, and pressure against the strongest evaluated opponent. Opponent reputation is an estimate from public counts, not hidden values.
- [aiSearch.ts](../../shared/eclipse/aiSearch.ts): Hard/Expert already search through own action boundaries, resolving intervening choices and opponent actions. They use bounded beams and sampled hypothetical worlds from [aiWorld.ts](../../shared/eclipse/aiWorld.ts), filtered views for each policy, and an independent simulation seed. This is **not** simply four or five button presses, nor an exhaustive optimal search. Hidden inventory sampling is an approximation, not knowledge of the real decks.

## Prioritized, source-backed experiments

These are proposed improvements; the “gap” column describes an inference from code inspection, not a demonstrated measured weakness.

| Priority and source | Conditional hypothesis | Current support and remaining gap | Meaningful counterexample test |
| --- | --- | --- | --- |
| **1. Fund the whole conquest** — S1, S2, S4 | Price research → upgrade → build → move → population removal → control as a plan. Reserve control discs and enough upkeep money; use the fleet where it produces the best point swing. | Search can simulate sequences, but fast research/build bonuses do not explicitly reserve the final claim or compare complete target plans. Occupation evaluation approximates population clearance and can overvalue an unclaimable win. | Two apparently identical winning invasions: one can clear population and claim; one exhausts all discs or cannot bombard. Prefer the realizable gain. Verify actual end-round control/scoring, not a weight constant. |
| **1. Ancients are opportunities, conditionally** — S1, S2 | Retain profitable Ancient sectors when an affordable fleet can clear them before rivals; discard a blocking draw when material/route constraints make it unusable. | Exploration resolution mostly counts VP, squares, and faction Ancient bias. It does not build a target-specific preparation timetable. Existing Improved Hull preference is broad; Plasma Cannon is not given the same explicit Ancient-plan synergy. | Compare material-rich opening with a material-starved Hydran opening and a Planta last-exit blockage. Test available cheap basic-part/Shield alternatives when Improved Hull is absent; no invented market draws. |
| **1. Matchups, not shopping lists** — S1, S2, S4 | Research/refit the cheapest improvement that changes a relevant fight or conquest outcome. Neutron Bombs depend on populated targets, cannon capability, counters, range, and time to attack. | Combat-aware movement exists; research and upgrades use more generic component values. There is no equivalent target-matched research→refit comparison. | Improved Hull should help an early exposed Ancient-hunting fleet, but lose to a necessary counter or immediate scoring purchase when it will never be installed. Neutron Bombs should differ for missile-heavy conquest, unpopulated targets, and an enemy with Neutron Absorber. |
| **1. Marginal economy, including Money** — S1, S2, S4 | Compare actual income unlocked, colony ships/cubes, remaining rounds, control rent, and alternative uses of the action. A Money-only sector can be the action that enables the whole plan. | Sector evaluation already values scarce Money. Its cheap population ranking is less constrained than the deeper evaluator; generic science/material values and short horizons can miss a bottleneck. | Same Money-only sector under an impending upkeep shortfall versus abundant cash and a better target. A science-rich square with no eligible cube/colony ship must not deliver imaginary immediate income. Never encode “ignore all gold sectors.” |
| **2. Reputation is marginal** — S1-comment, S2 | Value a fight by likely improvement to the current rack plus discovery/territory, not a full nominal reputation payout each time. | Exact private kept tiles and public opponent counts are available. A generic combat incentive remains in movement scoring; no explicit per-candidate expected rack improvement is evident there. | Same low-value battle with an empty rack and a full high-value rack. A dangerous extra battle must not earn fictitious full-rack points. Base private-random and house-rule public-deterministic reputation need separate evaluators. |
| **2. Batch without missing the moment** — S1, S2 | Concentrate upgrades/builds when waiting is safe; interrupt the batch for urgent defense or an expiring target. Preserve material reserves only when they have a plausible use. | Coordinated candidates and deployed-hull upgrade weighting exist. Threat urgency and the value of idle reserves are coarse; permanent hoarding or automatic maximum fleets would both be regressions. | Two-cruiser batch versus an immediate single-ship defense; same reserve in a safe rear sector versus a threatened frontier. Test movement against real connections/pinning, not geometric adjacency alone. |
| **2. Passing is an opportunity cost decision** — S1, S2 | First-pass benefits can outweigh a marginal action, but a later reaction is never guaranteed. | Search models opponent turns and round transitions; the fast pass score mainly sees money balance. | Passing with opponents still pursuing legal actions versus being the final unpassed player. The latter cannot assume a subsequent reaction. Assert reactions spend an influence disc and give only one activation. |
| **2. Orbitals and research buy usable future output** — S2 | Compare the whole research/build/colonization chain with trading, defending, or taking points now. | Early Orbitals have generic bonuses; deeper evaluation sees population and material reserves but does not explicitly rank full payback plans. | Early protected, material-rich colony-ready position versus late, threatened, or colony-starved position. Include an expensive rebuild opportunity cost, not only gross production. |
| **3. Choose the scoring portfolio and target** — S2, S4 | Convert the final useful actions into territory, monoliths, tech-track points, or a leader-denying capture. Price diplomacy against economy, rack space, traitor cost, and future attack access. | Exact score evaluation and leader pressure exist; the fast movement “leader” proxy is sector count. Diplomacy decisions mostly compare capacity and static values. | A smaller empire leading on public tech/monolith points versus a larger low-scoring empire; compare equivalent legal captures by net swing. Late ambassador acceptance should account for a valuable full rack and an imminent profitable invasion. |

Faction policies should express these conditions through capabilities: starting combat strength, build/refit efficiency, material scarcity, exploration choice, coexistence, and alternate scoring. Do not teach a custom faction a base-species stereotype before its board, economy, and rules are implemented. S1’s suggested two-cruiser opening is a candidate recipe, not a mandatory opening for every species.

## Computation and evaluation plan

Keep the current [difficulty budgets](../../shared/eclipse/aiConfig.ts) initially:

| Difficulty | Current planning limit | Role |
| --- | --- | --- |
| Normal | No deep search; 500 ms configured budget | Better cheap conditional ranking and bounded matchup work. |
| Hard | Up to depth 4, 180 nodes, 3 seconds | Two-world, narrow-beam action planning. |
| Expert | Up to depth 5, 600 nodes, 30 seconds | Three-world, wider-beam planning; stop earlier when bounded work completes. |

These are search limits, not measured p95 response times or a proof that an individual synchronous simulation cannot overshoot a deadline. [Server workers](../../convex/eclipseMatches.ts) already compute off the browser, track remaining budget across a turn’s command chain, and commit only after revision/lease validation. Forced choices use the fast policy. Preserve that architecture; do not grant another 30 seconds for each installation, hit allocation, or activation.

First experiment: spend existing work on a few diverse, target-specific preparation candidates instead of increasing depth. Use cheap reachability/payback screening; consider at most three promising targets and a few legal fleet recipes per target. Reuse public-matchup results for equivalent blueprints, damage, battle stage, and faction abilities. Bound caches per invocation. Any additional Monte Carlo trials must come from an explicit shared work allowance; do not multiply simulations by every technology, slot permutation, and beam node. Measure fallback work too. These proposed caps require profiling rather than being performance claims.

Validation before adopting a policy change:

1. Write the paired scenarios above as failing behavioral tests, then evaluate legal authoritative outcomes. Allow equivalent good plans; avoid brittle assertions that simply encode the new weights.
2. Run fixed-seed, seat-rotated matches at every supported player count and every implemented faction, against both the existing AI and the simple legal baseline. Separate tuning seeds from holdout seeds. Include scarce technology, bad exploration, rich peaceful, contested center, bankruptcy, and late-game fixtures.
3. Report paired win rate, VP difference, eliminations, wasted/unusable preparation, unclaimed victories, and resources stranded at scoring. Give sample counts and uncertainty; an aggression increase is not itself success. Use meaningful minimum gains and latency limits agreed before evaluating the holdout set.
4. Measure server wall time, nodes, completed depth, cutoff rate, and memory by difficulty/player count. Test deadline fallback, interrupted/retried work, and human takeover separately from policy quality. Run memory-bounded batches.
5. Keep fairness invariants: changing hidden enemy reputation/deck order while the public view stays identical cannot change recommendations for a fixed simulation seed; search cannot mutate authoritative RNG/state; identical inputs and fixed work limits replay deterministically. Time-bounded searches may finish different depths, which diagnostics must explain.

Acceptance would require improved holdout outcomes within the existing budgets, all rules/privacy/replay checks passing, and no regression to needless fleet accumulation or unclaimable attacks. No benchmark was run and no improvement is claimed by this research-only change.

## Decision and follow-ups

Start with complete conquest budgets, Ancient preparation, and conditional tech matchups. The archive reinforces the need for an opponent that exploits advantages, but repeatedly argues against a universal build order. Defer larger search depths until candidate quality and evaluation improvements have been measured. Keep ten-/twelve-round and public-reputation policies behind explicit future ruleset support; preserve the base-game evaluation meanwhile.
