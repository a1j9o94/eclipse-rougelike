# False browser offline indication

Outcome: a working connection to the authoritative game server enables play even if the browser reports navigator.onLine=false.

Acceptance: healthy socket + offline hint allows profile access and game creation; session loading still times out with recovery guidance; genuine socket loss disables authoritative commands until reconnect. Browser offline indication is advisory, not proof of server reachability. Preserve credentials and existing saves. User's exact OS/browser cause remains unconfirmed.

Tests first: ConnectionStatus healthy socket/offline hint and stalled session/offline hint regressions; real-browser navigator.onLine override against the existing app before the fix. Retain existing real disconnection/retry tests. Changed lint, relevant bounded tests, build and Vercel live verification required.

Risk and rollback: Convex detects actual socket loss, which may follow a network change briefly. Submission always remains server-validated and revision checked. No storage or backend schema changes. Roll back frontend if required; no saved-state changes.

Decision: use Convex's `isWebSocketConnected` directly for mutation guards and disabled controls. Evaluate the browser offline hint only when that socket is disconnected. Keep session-init timeout active when the socket works even if the hint is false. This follows [MDN's navigator.onLine guidance](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine), which warns against disabling features based on this heuristic.

Observed reproduction: an actual browser with navigator.onLine overridden to false connected to the production backend, received query data, yet the old release disabled room creation. This confirms the application's false-offline bug; it does not identify the underlying reason for the user's browser flag.

Local result: 11 focused tests pass, scoped lint clean, production build passes. Real-browser forced-offline-hint flow enables profile/sign-in and solo creation; forcibly closing the websocket disables command submission; reconnect restores submission and accepts exploration with the offline hint still false. Credential preserved; zero page errors. Full lint remains inherited 88 errors/12 warnings.

Independent connection-review agent: checked the implementation and actual before/after images. A healthy socket now takes precedence in both mutation guards and status rendering; a loading player session still gets the recovery deadline. The browser harness closes the actual routed websocket rather than equating a simulated OS offline flag with transport loss. On real socket loss the draft confirmation is disabled and the board explains that it is waiting to reconnect; after restoration the original draft can be accepted. No identity reset occurs. Reviewed red lobby, corrected lobby, and disabled game-command screenshots at 1440×900; no new clipping or layout defects. Final live false-offline verification passes on `https://eclipse-rougelike.vercel.app` after deployment. With the browser's offline hint forced false throughout, profile/sign-in controls are usable, a solo room starts, real websocket loss disables the draft confirmation, and reconnect permits the exploration command to save revision 1. The browser retains its identity and reports zero page errors. The initial live run timed out in a raw `textContent` polling selector; the harness now waits on the accessible confirmation button becoming actionable, then submits through that same button. Evidence: `second_dawn_false_offline_browser/live/result.json`, its three screenshots, and `logs/second_dawn_false_offline_browser_live.out`.

This is separate from the agent-operated browser reproduction and confirms the practical result on the previously failing setup; the underlying OS/browser reason for its false reachability hint remains unknown.

The existing recovery browser harness initially timed out because Playwright's offline emulation left its routed websocket open. That case is now correctly treated as connected by the application. The harness now explicitly closes/blocks routed sockets while applying the offline hint, then restores both. Blocked connection, ten-second retry guidance, identity-preserving reload, actual disconnect and automatic recovery all pass. No product rollback or browser-hint veto was reintroduced.
